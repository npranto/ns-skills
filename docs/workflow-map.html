Find what you have in hand. Unsure? Run /ns-route <task> and it classifies the task, picks the workflow, and adjusts it for risk, security, data, and scope.

Run modes

Four ways to run any workflow

Every file edit is approved by you, one file at a time, in every mode except "hand to an agent", where an agent works alone in its own worktree and you review what it decided before anything merges. Autopilot needs an interactive session (terminal, IDE, or Herdr pane) because of the approvals.

By hand

Pick "by hand" at /ns-route and it prints every station as an exact command with its real arguments, or type each one from the line yourself. Files on disk carry the handoff, so clearing context between steps is safe. Lost your place? /ns-route status.

/ns-route status

Flow, step mode

Run the flow command. It pauses after every station to ask: continue, redo, or stop.

/ns-flow-feature "wishlist sorting"

Flow, autopilot

Add --auto. It asks its setup questions once, then runs to the end, stopping only at diamond stations.

/ns-flow-feature "wishlist sorting" --auto

Hand to an agent

An agent builds a low or medium risk ticket alone in its own worktree and comes back with a review-ready PR and a list of what it decided without you. You review, then ship it through the release card. You can also send any flow command to another Claude session or Herdr pane to run it there with your approvals.

/ns-flow-delegate <ticket> <ticket>

Autopilot answers for you

  • Continue, redo, or stop between stations
  • The quality-check stage plan and Run or Skip per observe check (recommended choice)
  • Branch name and base, docs scope, the understand brief's closing question
  • Offers to write an artifact (the file write itself still needs your approval)
  • Optional extras the workflow does not require, such as a shareable stakeholder page: skipped

Always stops for you

  • Every project file change
  • Decisions in grill, wayfinder, architect, and design; ADRs; the High-tier observation window and rollback threshold
  • Approvals: spec, tickets, split-ticket breakdown, a bug's fix plan, restated scope for a task with no ticket, scope-check trims, flags, and design choices, which review findings to fix, integration-check gaps
  • Every commit
  • Push and open the PR (which also approves that PR's reports and evidence page), the release card (your answer is the merge), promote, a flag change, rollback, destructive data changes, external tracker writes, any other comment or published page
  • Anything that could lose uncommitted work
  • Trouble: missing input, an escalation, a phase that fails twice, UNHEALTHY, NOT CLOSED, unexpected errors
